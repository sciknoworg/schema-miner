Workflow Description

SCHEMA-MINERpro progresses through four stages, moving from a process specification to a refined, ontology-grounded scientific schema. Each stage has a defined input, output, and validation signal so that experts can inspect and guide the workflow.

Stage 1

Initial Schema Mining

Generate a first JSON schema from a process specification document.

Example: ALD specifications produce top-level fields for reactants, process conditions, film properties, safety, and stability.

Input variables
LLM_PROVIDER, LLM_MODEL, PROCESS_NAME, PROCESS_DESCRIPTION; provider credentials such as HuggingFace_Access_Token or SAIA_API_KEY/SAIA_BASE_URL.
Input files
data/stage1/process.txt with process name: and process description:, plus data/stage1/process-description.pdf.
Output files
data/stage1/schema/<model>.json and data/stage1/schema/stage1.log.
Review files
data/stage1/feedback/<model>.txt stores expert feedback used as input to Stage 2.

Stage 2

Preliminary Refinement

Refine the initial schema using a small expert-curated scientific corpus.

Example: Feedback can request missing units, merge duplicate properties, or reorganize nested process fields.

Input variables
batch, available_batches, schema_path, feedback_path, papers_dir, and results_dir, alongside the provider/model variables from Stage 1.
Input files
For batch1: data/stage1/schema/<model>.json, data/stage1/feedback/<model>.txt, and data/stage2/batch1/*.pdf. For batchN where N > 1: data/stage2/schema-batch{N-1}/<model>.json, data/stage2/feedback-batch{N-1}/<model>.txt, and data/stage2/batchN/*.pdf.
Output files
data/stage2/schema-batchN/<model>.json, data/stage2/schema-batchN/stage2-batchN.log, and per-paper intermediate files under data/stage2/schema-batchN/intermediate-schema/<model>/.
Review files
data/stage2/feedback-batchN/<model>.txt records expert review for the next Stage 2 batch or the Stage 3 starting point.

Stage 3

Final Refinement

Generalize and validate the schema against a larger, non-curated corpus.

Example: Stage 3 separates ALD growth behavior fields such as growth per cycle and nucleation period.

Input variables
batch, available_batches, schema_path, feedback_path, papers_dir, and results_dir; Stage 3 resolves the latest reviewed Stage 2 checkpoint for its first batch.
Input files
For batch1: latest matching data/stage2/schema-batchN/<model>.json, data/stage2/feedback-batchN/<model>.txt, and data/stage3/batch1/*.pdf. For batchN where N > 1: data/stage3/schema-batch{N-1}/<model>.json, data/stage3/feedback-batch{N-1}/<model>.txt, and data/stage3/batchN/*.pdf.
Output files
data/stage3/schema-batchN/<model>.json, data/stage3/schema-batchN/stage3-batchN.log, and per-paper intermediate files under data/stage3/schema-batchN/intermediate-schema/<model>/.
Review files
data/stage3/feedback-batchN/<model>.txt is needed only when another refinement batch follows; the final schema is the input to ontology grounding.

Stage 4

Ontology Grounding

Ground schema properties to formal ontology concepts and units.

Example: Temperature maps to a QUDT temperature quantity kind, while dosing time may be revised to domain-preferred units.

Input variables
--ontology-grounding set to prompt or agentic, --schema pointing to the final schema JSON, and RESULTS_PATH for the grounded output directory.
Input files
A final schema such as data/stage3/schema-batch2/<model>.json or a benchmark schema from results/stage-3/.../*.json, plus QUDT/OLS ontology terms retrieved during grounding.
Output files
Ontology-aligned JSON saved under RESULTS_PATH; reference outputs include results/Ideal Schema/Atomic-Layer-Deposition/*-with-qudt.json and results/Ideal Schema/Atomic-Layer-Etching/*-with-qudt.json.
Validation
Expert review verifies lexical matches, FAISS semantic matches, QUDT quantity kinds, units, URI metadata, and any LLM-assisted grounding decisions.

Results Snapshot

The evaluation compares schemas generated by GPT-4o, GPT-4-turbo, and LLaMA 3.1 (8B) across refinement stages. Quantitative metrics capture schema variance, while qualitative review identifies model stability and grounding quality.

Representative Stage 3 Experimental Schema Similarity
Use case Model pair ROUGE-L BERT-F1
ALD GPT-4o vs GPT-4-turbo 0.3690 0.8046
ALE GPT-4o vs GPT-4-turbo 0.3552 0.7631

Primary quantitative metrics: ROUGE-L, BLEU, and BERTScore. See the paper for the complete cross-stage matrices.

Qualitative Findings

For ALD, GPT-4o and LLaMA 3.1 (8B) maintained the most coherent schema structures across refinement stages. For ALE, GPT-4o and GPT-4-turbo were the most reliable at capturing the process structure. The hybrid grounding strategy reduced unnecessary LLM calls by using direct ontology lookups before semantic search.
